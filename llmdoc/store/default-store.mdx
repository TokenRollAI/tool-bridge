# 部署级 Default Store

`default` Store 是部署级私有对象能力，设备产物不必挂载 Context。稳定身份为 `store://default/<objectId>`，不是 bearer；知道 URI 不授予读取权。Context 是命名语义数据源，Store 是 opaque 对象，两者的 owner、授权与 namespace 不混同。

## 权威与身份

`StoreService` 拥有 owner/producer、上传声明、授权、状态机、分享与清理；`StoreRepository` 拥有跨记录原子操作；`StoreBackendResolver` 根据不可变 backendId 取字节服务。标准 Node 用 PG 领域仓库和 S3，不能把通用 KV CAS 当作同等原子替代。

对象/session 固定 backendId，active 切换只影响新上传。PG `beginUpload` 在一个事务里绑定幂等身份、active backend、call reservation、对象与会话；`finishUpload` / `terminateUpload` 同时推进对象和会话。字节 I/O 在事务外完成，服务层处理“字节成功但 metadata 未提交”的恢复，不把 S3 网络延迟留在 PG 事务内。后端的 FK 引用与切换规则见 [存储后端](./storage-backends.mdx)。

owner 是稳定 OwnerRef，SK 换钥不改变对象归属；producer 记录实际产出者。普通上传 owner/producer 都是当前身份；call 上传 owner 是 caller、producer 是 device，并绑定 originCallId。只有 ready 对象可读/分享/进入 owner 列表；pending、failed、abandoned、deleted 不可见为可读对象。

幂等绑定分别处于 owner 或 producer+call 域，同声明恢复同对象/会话，身份或声明冲突返回 conflict。call 配额是累计 reservation，不因为上传失败/删除对象就返还后允许重复绕过累计限制。SDK 的本地 size 检查只是早拒，服务端事务才是额度权威。

对象 key 由服务端生成并落在保留 `__tool_bridge_internal__/store/v1` namespace，filename 只是展示元数据。Context 与保留根重叠的非空 prefix 挂载拒绝；空 prefix 仍过滤 list/search/read 并拒绝写入保留 key。常规 cleanup 不把无 Store metadata 的字节猜作 orphan，因为它们可能属于 Context。

## 上传与权限

普通 SK 经 `system/store/create_upload|complete_upload|abort_upload` 控制上传；请求只声明 size、MIME、checksum、filename、幂等键，不接受 context/path/overwrite。grant 含 objectUri、uploadId、transport、url、headers、期限、maxBytes 与 uploadToken，整体按 secret 处理。

标准 Node S3 driver 使用 relay：`PUT /~store/uploads/<uploadId>` 用 `x-tb-store-upload` 认证，流式硬限额后写 create-only 字节，再原子提交 ready，正常 PUT 直接返回 descriptor。客户端无需再 complete；崩溃恢复可显式 complete，并由服务端 HEAD 校验。complete 幂等，未有合格字节时 conflict；ready 对象不能 abort。

接口仍允许显式实现 `presignPutExact` 的 driver 使用 direct：必须声明精确 size，把 Content-Length、Content-Type 和 create-only 条件纳入签名，再由 complete/HEAD 校验。未知 size、仅普通 presign 或无法 enforce 硬上限时一律 relay。标准 AWS adapter 没有 signer，不把通用协议分支误写成已交付浏览器直传。

上传是整对象 single PUT，无 multipart/resumable；失败重传整个对象。checksum 只有可验证的后端 metadata 才进入可信 descriptor，客户端声明不能替代实测大小。上传源中断、超限、deadline 和重复 create 必须通过真实 S3 wire 验证。

## 设备 call capability

网关给已鉴权 realtime call 的 JSON frame 下发窄 `context.upload`，绑定 caller owner、device producer、call id、期限、数量、总字节、单对象大小和 MIME。SDK 在调用用户 handler 前移除原 token，handler 仅看到限额并可调用 `call.uploadObject`。create 使用 `x-tb-store-capability`，relay/complete 使用 upload token；token 不进入 arguments/result/URL。

call 完成、取消或失败后 best-effort revoke，期限和 cleanup 是硬兜底。设备自主上传可用顶层 uploadObject 和普通 HTTP Bearer，此时 owner/producer 均为设备。Mailbox 不复用 realtime capability：Mailbox handler uploadObject 明确 unavailable，不能持久化或延长 call token。

## 读取、分享与管理

stat/read/list 要 read，上传/share/revoke/delete 要 write，仍须对象级 owner 检查；跨 owner 用 not_found 隐藏。owner 列表通过 PG owner/status 索引直接分页。descriptor 只包含稳定身份与公开 metadata，不返回 driver key、token 或签名 URL。

read 返回短期 owner ref，share 创建有期限的匿名 bearer；下载时仍核对象 ready，share 另核撤销/到期。delete 先条件标记不可读，再幂等删字节，因此旧 ref 即时失效。upload/call/share 权威记录只持 token hash 与 signingKeyId；refs 携 kid，签名 keyring 退役规则见 [密钥维护](../hosts-deploy/maintenance-and-keys.mdx)。

capability-only 控制面在普通 SK 鉴权前只按对应 header 进入窄权限，不能从 body 接受 capability/uploadToken/shareToken 等 secret 字段。所有无效、过期、跨 owner 或非 ready 的 bearer 读取折叠为 404；日志与错误脱敏 token path、headers 和签名 URL。

Store URL 保持当次请求的 alias host/port；TLS 代理后的 canonical origin 只提供可信 protocol，不用客户端 X-Forwarded-Proto，也不把所有用户改到 canonical host。neutral client 的同源校验不能为适应错误 URL 被放宽。

## 宿主清理与嵌入

Node prepare 初始化 PG schema/后端，监听后异步启动有界 cleanup，周期使用已应用设置，慢 tick 不重入。metadata 控制过期会话、share/call、幂等绑定与终态对象的清理；字节删除成功先记录 bytesDeletedAt，安全窗口后再删 metadata。与 complete 竞争时重新核状态，不得删除已经 ready 的字节。

app/SDK 没有非原子的生产 fallback：嵌入者若要 Store，显式注入 repository、backend resolver 和稳定签名根/keyring。内存对象与领域替身只适合测试/明确易失场景。`objects` 注入本身不等于 Store 完整可用。

## 客户端与当前边界

`@tool-bridge/sdk/store` 是 wire parser、transport、grant/upload 状态机与敏感错误裁剪的共同真源。CLI `tb store` 与 Dashboard Store 页复用它；Dashboard 只保留 File/session 和 Query cache 适配，不复制 relay/direct 时序。

CLI upload 新建 opaque 对象，get 默认二进制 stdout，--out create-only；分享只在用户显式请求后交付短期 ref。Dashboard 按 profile 隔离 owner 列表与 cache，bearer 不进 toast、调用历史、localStorage 或浏览器 URL。Context 的 ctx put/upload 继续 author 命名 entry 并返回 node://，不能悄悄改成 Store URI。

当前只提供 default、短期匿名 share 和 single PUT，无 named Store、永久公开发布、主体总占用量/淘汰或自动 S3 后端数据迁移。Store URI 也不自动变成 MCP image/resource，消费者须显式按当次权限读取。
