# Workers KV 语义

KV 是最终一致存储，不是事务数据库。代码必须把 list/get、写入传播和删除传播之间的竞态当作正常状态。

## 读路径

- `list(prefix)` 返回 key 后，紧接的 `get(key)` 仍可能为 `null`；跳过该项，不得解引用崩溃。
- 分页必须完整消费 cursor，并为每页的 get 控制并发，避免触发 Workers subrequest 上限。
- 树查询尽量用路径前缀收窄，不做全 namespace 扫描后在内存过滤。
- 派生索引或状态项缺失时返回降级结果；读操作不得顺手写回权威记录。

## 撤销与一致性

SK 撤销、节点删除和 online 状态在跨 PoP 传播期间可能短暂不一致。安全下界应由请求时权限校验、短缓存 TTL 和 fail-closed 共同提供；不要在文档承诺一个未经平台保证的精确传播秒数。

需要“立即全局生效”的语义时，KV 不是合适的唯一真源，应通过架构选择解决，而不是叠加无界重试。

## 测试

- 单测覆盖 list 返回幽灵 key、get null、分页 cursor 和部分失败。
- Miniflare/Workers pool 覆盖绑定配置和真实 API 形状；使用仓库当前 Vitest pool 配置，不复制过时示例。
- 真实环境验证只证明一次观察，不把采样延迟写进长期契约。

KV 中不得保存明文 secret。SecretStore 即使落在 KV，也必须先由宿主密钥加密，并避免把密文、nonce 或错误上下文原样暴露给普通管理响应。
