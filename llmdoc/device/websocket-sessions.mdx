# Node 设备会话、presence 与 SDK device

Node 的 `DeviceHub` 持有活 WebSocket、连接 generation 与本进程 call 去重；`DeviceRouter` 提供可选 Redis 跨副本路由。PG registry 保留设备与发现信息，重启后设备需重连，不能把持久 registry online 位当成活 socket 或持久执行结果。

## 不变量

- 设备帧使用 core 稳定 codec，ping/pong 字面量由共享常量产生；socket 生命周期驱动心跳与在线状态。
- `lastSeenAt` 与 TTL 只在发现投影中把过期 online 降级为 stale，读路径绝不回写下线；权威 online 由连接生命周期维护。
- close/error、替换连接、孤儿清扫与回收都须有 generation guard，旧连接不得覆盖新连接。启动 sweep 发现没有活 socket 的崩溃态时同步下线 registry。
- `deviceLifecycle.ts` 统一调用前 keyId/registerPaths/保留根重验、断线下线和“先标记 search 脏 → 删 canonical 子树 → 清索引”的回收顺序。`deviceHello.ts` 在落库前拒绝规范化路径冲突，DeviceHub 不复制这些安全链。

## 为什么保留 raw WebSocket

设备反向注册的稳定 wire 是 raw WebSocket 上的 core JSON frame，不是 Socket.IO/Engine.IO 协议。Socket.IO client 不能直接连接当前 endpoint；同时更换两端也不会代替 generation、presence、reclaim、call/result/cancel 或 Store capability 这些服务端权威状态机，反而增加第二层协议。因此服务端保留 raw WS；客户端可使用 PartySocket 的 reconnect transport，但不引入 PartyServer/rooms 来重新定义连接归属。

可复用的边界是 `@tool-bridge/sdk/device` 的 portable connection supervisor：它持有 reconnect、heartbeat、credential refresh、suspend/resume 与 call dispatch；Node CLI、React Native 等宿主只注入 WebSocket factory 和凭证 provider。CLI 的 `deviceRuntime.ts` 可保留 shell/FS/structured process dispatch 与 `ws` adapter，不得复制 supervisor 状态机。任何未来协议替换都必须先证明上述连接代际、权限和执行歧义不变量仍可保持，不能只以 rooms/reconnect API 更便利为理由。

## Durable Mailbox 与 WebSocket 的分界

Mailbox 是独立的 pull-only operation authority，详见
[Durable Device Mailbox](durable-mailbox.mdx)。本 guide 只拥有 realtime frame、presence、socket
generation 与 connection supervisor；当前没有 Mailbox WS hint，Device SDK 的 hello/handler/frame 也没有
为 Mailbox 增加另一条 WS 协议。普通 command POST 的 `~delivery` 可选择 realtime、mailbox 或 fallback；
fallback 仅在本节 realtime 生命周期明确给出 `not_dispatched` 时转入队，`completed` 或 `unknown` 不入队。
claim/lease/journal/cleanup 仍不经过本节 WebSocket 状态机，而由现有 pull processor 与 installation-local
durable journal 处理；单一 device credential 只有一个活跃安装仍是幂等语义前提。

## Linux process 暴露与终态

Linux CLI/daemon 的 structured command profile 只是在已有 `DeviceExpose.nodes` 中产生 `kind:'tool'` 节点,
command metadata 携带 strict input/output schema、设备所有者声明的 effect 与 confirm。wire 继续使用既有
hello/expose、call、result、cancel,没有增加 operation frame 或另一套调用协议。任意 `shell/exec` 仍保持
`effect:destructive + confirm:true`,不能按 shell 字符串或命令名启发式降级。

shell 与 structured command 的最终结果保留 `stdout/stderr/exitCode`,并附加
`startedAt/completedAt`、`outcome: exited | signaled | timed_out`、可选 signal 以及两条输出流各自的截断标志。
正常非零 exit code 仍是 `outcome:exited`;调用方必须检查 exitCode/outcome,不能把收到 result 当作业务成功。
timeout 会杀直接 child 并返回 `timed_out`;structured handler 收到协作式 AbortSignal 时也会杀直接 child,
但没有独立 `cancelled` outcome,也不承诺清理其自行派生的全部 descendants。现有 shell dispatch 没有传入同一
AbortSignal。

这些字段只在一次同步 device call 收敛后的最终 result 中出现；同步路径仍没有 `start -> operationId`、
status/poll、增量 stdout/stderr 或重连恢复。另行选择 mailbox delivery 时才产生公开 operation，并且只保存
最终 JSON result/error，不把 stdout/stderr 改造成流。两条路径的 cancel 都是协作式提示；副作用无法从
终态证明时不得盲目自动重试。

## 验证

共享帧/业务单测验证协议，Node listener + 真实 socket 测试验证注册、重连、presence、旧连接拒绝和 realtime 调用；多副本另用真实 Redis 验证路由与断连。`scripts/verify-device.ts` 是可授权的部署 smoke，不用固定等待或重试掩盖 generation/回收错误。真实服务证据与本地集成测试分开记录。

## SDK device 运行时边界

设备客户端的 npm 消费面分为 Node-only 根入口与独立的 `@tool-bridge/sdk/device` neutral 子入口，后者供 React Native/Hermes 等宿主使用。约束与经验:

- 多运行时包的兼容性按**目标子入口的 JS/d.ts 依赖闭包**判定,不按包级 `engines`/`dependencies` 猜测。`ws` 可以继续被 sdk 安装,但不得进入 device 子入口的模块图;JS 与声明文件两条依赖图要同时隔离。
- 设备核心以 WebSocket factory、credential provider 和显式 suspend/resume 注入宿主差异;RN 第三参数 headers 只存在于薄 adapter。
- 拍照等二进制产物不新增 WebSocket 二进制帧。网关为每个已鉴权 call 把窄 Store capability 放进
  wire `context.upload`(`token/expiresAt/maxBytes/maxObjects`)。SDK 在进入用户 handler 前删除原始 token，
  handler 的 `context.upload` 只含期限/限额，并获得
  `call.uploadObject({body,contentType,filename?,size?,checksum?,idempotencyKey?})`。它经普通 HTTP 创建
  upload session；只有 create 携带精确 size 且 backend 能签 `Content-Length` 时走 S3 direct，否则
  relay。result 帧只返回 JSON 可序列化的 ready descriptor/`store://default/...`。owner 是 caller，
  producer 是 `device:<deviceId>`。
- `call.uploadObject` 会把 create capability 放进 `x-tb-store-capability`、把 session capability 放进
  `x-tb-store-upload`，不会塞进 arguments、result 或 URL；网关在 call 结束后撤销 create capability，
  期限与后台清理兜底。SDK 只用已知 size 做本地早拒，不在 create 成功前自行递增对象计数；数量/字节
  reservation 与幂等 replay 以服务端领域事务为准。call idempotency 还绑定 producer + call id，不能跨 call
  恢复 session。老网关不带 upload 时明确 `unavailable`，不能悄悄退回 Context。
- device 子入口也保留顶层 `uploadObject`，使用 `purpose:'http'` 的设备 Bearer 身份做自主 Store 上传。
  旧 `uploadContextObject` 已删除。Context 的 `create_upload`、`tb ctx upload` 与 Dashboard Context upload
  仍保留为管理/authoring 能力，但不再是设备产物入口。
- 上传保持跨运行时流式：浏览器/RN 沿用 Web fetch，Node 原生 fetch 遇到 `ReadableStream` request body
  时 SDK 内部补 `duplex:'half'`；该运行时细节不进入公开 grant 或设备帧。
- realtime handler **执行结果**仍只保留进程内同 call id 去重(handler 获得 id 与协作式 AbortSignal)，与
  Store upload session、Mailbox journal 都不是同一件事。Mailbox 通过公开 operation id、lease 与宿主注入的
  durable journal 单独提供重启恢复；当前 Mailbox handler 的 `uploadObject` 明确 unavailable，不能借用
  realtime call-scoped Store capability。
- 发布验收不止看 manifest:检查全部条件导出目标、扫描 device 产物的 Node/私有依赖泄漏、从最终 tarball 干净安装并同时 import 两个入口(闸门细节见 [npm-publishing](../release/npm-publishing.mdx))。
