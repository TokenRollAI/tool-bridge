# Plugin 设计与迁移

先读 [插件运行时](plugin-runtime.mdx)。内置 plugin 与 gateway 同进程同权。外部分发和本地 dev 各有进程边界，适用各自的运行限制。

## 本地开发与热重载

```sh
tb plugin init notes
cd notes
npm install --ignore-scripts
tb plugin dev
```

`init` 生成 Node 项目、宿主入口、Dockerfile 和 release 清单示例。`dev` 按 `package.json#main` 加载默认导出的 `fetch(request, env)`，启动独立 loopback 网关。按输出在第二个终端执行 `source`，从私有临时文件取得当前会话 URL 和 SK，再用 `tb tree dev`、`tb help dev/actions` 和 `tb call dev/actions/greet '{"name":"Ada"}'` 验证。会话退出清理凭据文件。已发布项目需要把示例清单中的地址和版本替换为真实制品。

无必填凭据和挂载配置的 tool/Context 自动挂在 `dev/<export-id>`。其余 tool/Context 用 `--provider dev --export <id>` 手动挂载，保存后会重建挂载，网关的会话凭据与 secrets 在内存中保留。热重载先验证候选，失败时上一版继续服务。修改依赖后需重启。events export 需有事件仓库的网关绑定并验证。开发 worker 使用收窄后的环境，仍以本机用户权限执行，只加载可信源码。

## descriptor 规则

- 使用 `plugin/v2`，manifest 严格校验未知字段。
- 每个 export 显式给出 profile、kind 与凭证形态；无凭证也写 `auth:none`。
- 密钥写入 SecretStore，由节点 `authRef` 引用；`providerConfig` 只放会被管理面回显的非敏感配置。
- `~describe` 必须纯内存、无凭证、无网络，以便生成 catalog。
- 内置 plugin 同时提供 handler binding 与 catalog 描述；标准宿主直接挂载，不写运行时注册记录。
- Webhook 来源用 `plugin.events` 声明 `events/v1`、签名 header 与事件 schema，验签与入库边界见 [持久事件主题](../events/durable-topics.mdx#eventsv1-与-github-webhook)。

## 运行时下界

- env 经 `narrowPluginEnv` 收窄，不能把宿主全部 secrets 透传给 plugin。
- 所有出站使用 `guardedFetch`；默认 HTTPS，敏感 header/body 遇跨源 redirect 必须拒绝。
- 托管 plugin 未配置 `PLUGIN_TOKEN` 时 fail closed。
- OAuth client secret、多字段凭证与单值 token 不得互相 fallback。
- 错误、健康信息和日志不得包含 secret、Authorization 或原始敏感响应。

## 迁移流程

1. 固定旧 connector 的工具名、描述、输入/输出 schema 和关键错误语义。
2. 实现 provider 的 schema、client、handler 和 descriptor；通用传输放 runtime，不在每个 provider 重写。普通单值/header 认证与常规错误体使用 `createAuthedClient`；需要业务错误码、字段级或传输特例时声明 `mapError` / `mapTransportError`，不回到手写认证和通用错误映射。
3. 生成 catalog，并更新 `migration-fingerprints.json`。
4. 删除旧 connector 入口，验证三道闸门。

HTTP 抽象选择按权威与失败模型，不按 provider 名单：

- `createAuthedClient` 只声明常见 auth header 与错误消息提取，底层仍必经 `createProviderHttpClient` / `guardedFetch`。`errorMessage` 与整段 `mapError` 互斥，冲突要在 client 构造时失败。
- query/path/body auth、GraphQL `200` 内的 errors、raw streaming/协议升级等无法由该层正确表达的情形保留受审例外。直接 `guardedFetch` 还必须登记例外清单，不得退化为裸 `fetch`。
- provider 作者需要 `TBError`、`isTBError` 或 `normalizeUpstreamError` 时从 public `@tool-bridge/plugin-sdk` 导入，不建立对 private core 的运行时依赖。

迁移的 schema 形状规则只由 `scripts/migrate/normalizeSchema.mjs` 拥有，迁移执行器与 parity/report 只 import 它；不得在生成、比对两侧各写一份 normalizer。

三道闸门：

| 闸门 | 证明 |
|---|---|
| 等价 | 迁移前后公开工具与行为无意外漂移 |
| 形状 | descriptor/catalog、help 与 schema 一致 |
| wire | 真实 envelope 到上游请求、响应和错误映射正确 |

迁移脚本和 fingerprints 是持续回归约束，不是一次性历史文件。若确需改变公开形状，显式更新基线并在 PR 解释原因，不能让生成器静默覆盖差异。
