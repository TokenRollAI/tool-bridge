# 安全边界

## 身份与可见性

- SK 明文只在签发时出现一次,持久层只存 hash;disabled、delete、expiry 都视为失效。标准 Node 的权威状态来自 PostgreSQL，吊销即时生效。
- scope 按路径和 action 判断,deny 优先。无权看到的路径返回 404,避免通过 403 枚举树结构。
- `registerPaths` 限制设备/反向注册位置。target path、`registerPaths` 与内置/部署追加 `reservedRoots` 都以 canonical lowercase segment 比较，大小写不得成为绕过或静默全拒的差异。异步认证后还必须复核 active connection generation,防旧连接越权完成调用。
- `system/registry` 和 `~register` 各自先做通道 scope 判定，随后共用 `registryMutation.ts` 的 `assertNodeConfigMutation` 完成 register/root、secret ref、OAuth/config 与出站探测顺序。device hello 因输入形状不同由 `deviceHello.ts` 编排，但必须执行同一 register/root 约束，并在小写折叠后的 expose 路径冲突上 fail closed。
- Node 的 hello、调用前 device authority recheck 及 Mailbox claim/renew/complete 重验都必须携带同一部署 `reservedRoots`；不得让 WebSocket 或 Mailbox 成为绕过普通注册面的第三条通道。共享的重验/断线/回收业务序列由 `deviceLifecycle.ts` 拥有，宿主只持有连接代际与调度。

## 凭证

- 上游密钥只进入 SecretStore；节点记录只含 `authRef` / `skRef` / `oauthClient.clientSecretRef` 等引用。
  `providerConfig` 与 `oauthClient.clientId` 是可回显配置，不得存密钥；MCP OAuth 不得用 bearer `authRef`
  承载 client secret，也不得接受 inline `clientSecret`。
- MCP OAuth 的预注册 client 配置、DCR client 记录、access/refresh grant 分槽处理：预注册 confidential client 每次
  token 兑换/refresh 都从 SecretStore 解析 secret，public client 无 secret 且必须走 S256 PKCE；静态 client
  information 不写 OAuth StateStore。grant 绑定 authorization-server issuer、client id 与实际 redirect URI，任一变化
  都使旧 grant 失效；旧 DCR grant 只有在已存 DCR client 的唯一 redirect URI 可证明时才补 binding。
- 节点写入口对嵌套 `oauthClient.clientSecretRef` 执行与其它 secret ref 相同的 `system/secret admin` 使用授权，再验证
  引用可解析；顺序不能反，避免 SecretStore existence oracle。挂载、授权和调用各自验证所需状态。
- 标准 Node 的首次安装自动生成稳定根和 Admin SK，只有持本机短期配对凭证才能配置；已有 identity/initialized 的故障实例只走 recovery，不重新匿名安装。SDK 嵌入者显式提供初始 Admin SK，没有不安全引导开关。
- Linux structured command 的 child 缺省只继承基础环境白名单;显式 `inheritEnv` 只是按名称复制本机 daemon 环境,不是 SecretStore 引用解析,也不提供输出 secret redaction、执行后清零或到期保证。不得把 token/云凭证列入 profile 环境策略,也不得把 fixed executable/argv 当作 secret 通道。
- Device Mailbox 的 caller 权限在 enqueue 时快照：该次 call 授权成功后，caller SK 后续吊销不会自动取消
  operation；caller owner 或含命令叶子的完整 targetPath admin 才能查询/取消。这是 durable work 的显式授权语义，不得把
  claim 时重新校验原 caller 误当成更安全的默认。设备侧相反：claim/renew/complete 每次都走正常 HTTP
  Bearer 鉴权，并复核当前 credential keyId、registerPaths/mount 权限与 operation binding；设备 credential
  revoke/rotate 后旧 session/lease 不能继续推进。
- Device `fallback` 只能以 realtime 生命周期的显式 dispatch certainty 为依据：`not_dispatched` 才允许
  创建 operation；设备已返回业务错误属于 `completed`，可能写出 call frame 或已发送但未收敛属于
  `unknown`，两者都不得入队。禁止从 TBError code、HTTP status 或 retryable 猜测发送事实；`unknown` 对
  调用方固定为不可重试，避免同一副作用被 realtime 与 Mailbox 各执行一次。

## 出站

- remote、HTTP、MCP、plugin provider 都经过各自的 URL/host/环检测边界。generic remote 接受可选
  AbortSignal 与流式 response byte cap；federated search 及其 nested full-help hydration 都下发逐跳递减的
  remaining-time budget，并把 child body 限在部署上限内。
- remote allowlist 的 authority 解析必须与 WHATWG Fetch 的 special-URL 语义同形：反斜杠 `\` 与 `/` 一样终止 authority，不能把 `\@allowed-host` 误判为真实主机；像 `https:\\host` 这类不符合项目绝对 HTTPS URL 形状的输入必须 fail closed。先用与实际 fetch 一致的 parser 得到 hostname，再应用部署/运行时 allowlist，不得手切字符串猜 authority。
- 调用者 SK 不透传上游;只从 `authRef` 解析目标凭证。
- 内置 plugin 同进程同权,env 白名单和 `guardedFetch` 是代码强制边界。
- 跨源 redirect 不能携带 Authorization、自定义敏感头或 secret body；MCP OAuth token form 请求禁止自动 redirect，
  避免 authorization code、PKCE verifier、refresh token 或 confidential client secret 被 307/308 重放到新 origin。
- generic remote transport 对所有 30x 使用 `redirect:'error'`，不依赖 runtime 的跨源 header stripping，也不允许 same-origin 自动跟随。管理员必须把 `baseUrl` 配成最终 URL。
- remote `~help/~tree` 成功体是不可信协议数据：先过 strict wire 与 canonical path projector，拒绝编码分隔符、控制字符、过编码、root mismatch、非 direct child 与跨 node command；localized tree 后代重新执行外层 read/call 授权。

## 搜索

- SearchIndex 是可重建召回投影，不是权限真源；每个 hit 都从 canonical state hydrate，并重做 read+call、virtualize 与 effect。compact 只减少上下文，不减少授权检查。
- effect filter 只消费结构化 canonical effect，不从 prose 猜安全语义；SQL filter 后仍在 hydration 复核，防同步竞态。
- local cursor v2 虽加密认证并绑定 query/revision/ranking/options，仍不是授权凭据；每页重新鉴权。
- federated cursor 是固定尺寸随机 opaque handle，StateStore key 只存其 SHA-256。session record 绑定
  caller key/scopes digest、request、ranking 和每 hop topology，不保存 Authorization、SK 明文、baseUrl 或
  完整 schema；结构 parser 拒绝 credential/schema 字段。immutable generation 由 CAS 和原子 quota 约束，
  continuation 每次递归验证 child snapshot，并重新执行当前权限、secret、allowlist 与 canonical hydration。
- remote 只有声明且当次能解析 `skRef` 才参与联邦。未声明为 `unsupported`，声明但 secret 缺失为
  `unavailable`，两者均不出站；不可用 remote 不占有限 source slot。终端 caller SK 永不跨 gateway。

## 存储与日志

- 派生投影(presence、缓存、搜索索引)的 TTL/降级防御、stale generation guard 和崩溃后孤儿下线 属于安全下界,不是可删的历史兼容。
- 日志、错误、调用历史、URL、CLI argv 与一次性验证输出都不得回显 secret、Admin SK、OAuth token 或含敏感 args 的 payload。
- Presigned GET/PUT URL 本身是 bearer secret：客户端错误不得回显 fetch 原始 URL 或对象存储响应体，成功结果只持久化稳定 `node://` URI。写 grant 缺省把 `If-None-Match: *` 纳入签名以阻止静默覆盖，只有显式 `overwrite` 才扩大到可替换对象。
- Store 的 `store://default/...` 同样只是稳定身份，不是 capability；读取仍需 owner `read` 或短期 share。
  call/upload capability 只进 `x-tb-store-capability` / `x-tb-store-upload` header，相关 body 字段拒绝；
  `~store/refs|shares/<token>` path、presigned URL、headers 与 token 必须在日志/错误/历史中脱敏。无效 bearer、
  跨 owner 和非 ready 对象统一 not_found，避免对象 oracle。
- Store direct 不是普通 presign 的性能开关：只有请求声明精确 size 且 driver 的 `presignPutExact` 把
  `Content-Length`、`Content-Type` 与 create-only 条件纳入签名时才允许绕过网关；未知 size、旧
  `presignPut` 或 signer 失败必须退回受流式硬限额保护的 relay，complete/HEAD 仍做最终校验。
- Store HMAC key 优先由独立签名 keyring 的 active 根经版本化域分离派生，不把派生 key 写入 StateStore；权威 session/share/
  call capability 只存 token hash。设备 wire 上的 call token 由 SDK 内部消费，handler 的安全 context
  不暴露原始 bearer；客户端限额只做早拒，服务端领域事务 reservation 才是权威。
- Device Mailbox 把 arguments 与 terminal result/error 以 AES-GCM 加密后写领域仓库，AAD 绑定 operation id 与字段，keyId 指向 encryption keyring；Mailbox HKDF 域不与 SecretStore/Store HMAC 混同。服务端处理时仍持明文，这是 at-rest 而非 E2E。缺仓库或有效密钥 fail closed；重加密任务和旧根退役必须通过受保护维护与引用复核。
- Mailbox operation 的 payload、result/error 不进入 URL、日志、toast 或浏览器持久缓存；公开 summary
  只含 caller 快照、target、traceId、状态与时间。设备 installation journal 可保存 completion 用于重放，
  因而必须由宿主提供真正 durable 且受本机权限保护的存储，并按 expiresAt 清理。
- Context 与 Store 即使复用同一 ObjectStore 也属于不同授权域：`__tool_bridge_internal__/store/v1` 是
  强制保留根，重叠的非空
  Context prefix 挂载时 fail closed；空 prefix 挂载必须过滤/隐藏 Store read/list/search，并拒绝 write/update/delete/create_upload。
  Store cleanup 只相信权威 metadata，不把未知 driver key 猜作 orphan。
- relay filename 不参与 key；字节 driver 必须实施真实 create-only 条件写、流式大小/期限限制。终态对象在 DELETE 成功后先条件记录 bytesDeletedAt，再按安全窗口删除 metadata。
- storage/config/deployment/maintenance/keys 要求对应规范 system 路径的 admin；普通路径 write 不是管理权限。S3 凭证只进加密内部 secret，不回显 authRef/明文；不可变 backendId 和 FK 防止切换时旧数据漂移。
- S3 的实际 socket DNS 检查和 exact 内网 origin 例外归 Node adapter，不能把该能力推导成所有 provider HTTP 都有 DNS pinning。业务容器不持 Docker socket，外部 agent 只能执行指定 Compose app 的受限 schema。
- 配置模板不携真实资源 ID、域名、登录态与密钥。PG 之外的 bootstrap/root 文件和显式备份也属于 secret；API status 只投影非敏感状态。

## 评审规则

- 安全字段同时做客户端快速反馈与服务端权威校验;历史脏值无法证明安全时 fail closed。
- 删兼容代码时只删项目内部旧预览形状,不删 MCP 世代互操作、Help DSL 未知项忽略、S3-compatible 能力或真实上游差异。
