# 安全边界

## 身份与可见性

- SK 明文只在签发时出现一次,持久层只存 hash;disabled、delete、expiry 都视为失效。三宿主权威状态均为强一致 SQL 后端,吊销即时生效。
- scope 按路径和 action 判断,deny 优先。无权看到的路径返回 404,避免通过 403 枚举树结构。
- `registerPaths` 限制设备/反向注册位置;异步认证后必须复核 active connection generation,防旧连接越权完成调用。

## 凭证

- 上游密钥只进入 SecretStore;节点记录只含 `authRef`。`providerConfig` 是可回显配置,不得存密钥。
- OAuth client credential、access/refresh token 分槽处理;挂载、授权和调用各自验证所需状态。
- 首次 bootstrap 默认要求部署者提供 Admin SK。Workers 和 SDK fail closed;Node 仅保留显式 `TB_ALLOW_INSECURE_BOOTSTRAP=true` 的本地开发逃生口。

## 出站

- remote、HTTP、MCP、plugin provider 都经过 URL/host/环检测与超时边界。
- 调用者 SK 不透传上游;只从 `authRef` 解析目标凭证。
- 内置 plugin 同进程同权,env 白名单和 `guardedFetch` 是代码强制边界。
- 跨源 redirect 不能携带 Authorization、自定义敏感头或 secret body。

## 存储与日志

- 派生投影(presence、缓存、搜索索引)的 TTL/降级防御、DO hibernation 恢复和 stale generation guard 属于安全下界,不是可删的历史兼容。
- 日志、错误、调用历史、URL、CLI argv 与一次性验证输出都不得回显 secret、Admin SK、OAuth token 或含敏感 args 的 payload。
- Presigned GET/PUT URL 本身是 bearer secret：客户端错误不得回显 fetch 原始 URL 或对象存储响应体，成功结果只持久化稳定 `node://` URI。写 grant 缺省把 `If-None-Match: *` 纳入签名以阻止静默覆盖，只有显式 `overwrite` 才扩大到可替换对象。
- Store 的 `store://default/...` 同样只是稳定身份，不是 capability；读取仍需 owner `read` 或短期 share。
  call/upload capability 只进 `x-tb-store-capability` / `x-tb-store-upload` header，相关 body 字段拒绝；
  `~store/refs|shares/<token>` path、presigned URL、headers 与 token 必须在日志/错误/历史中脱敏。无效 bearer、
  跨 owner 和非 ready 对象统一 not_found，避免对象 oracle。
- Store direct 不是普通 presign 的性能开关：只有请求声明精确 size 且 driver 的 `presignPutExact` 把
  `Content-Length`、`Content-Type` 与 create-only 条件纳入签名时才允许绕过网关；未知 size、旧
  `presignPut` 或 signer 失败必须退回受流式硬限额保护的 relay，complete/HEAD 仍做最终校验。
- Store HMAC key 优先从部署信任根经版本化域分离派生，不把派生 key 写入 StateStore；权威 session/share/
  call capability 只存 token hash。设备 wire 上的 call token 由 SDK 内部消费，handler 的安全 context
  不暴露原始 bearer；客户端限额只做早拒，服务端 reservation/CAS 才是权威。
- Context 与 Store 即使复用同一 ObjectStore 也属于不同授权域：`__tool_bridge_internal__/store/v1` 是
  强制保留根，重叠的非空
  Context prefix 挂载时 fail closed；空 prefix 挂载必须过滤/隐藏 Store read/list/search，并拒绝
  write/update/delete/create_upload。旧 `store/v1` 不是授权边界，已有同名 Context prefix 继续可用。
  Store cleanup 只相信权威 metadata，不把未知 driver key 猜作 orphan。
- relay filename 不参与 key，本地 driver 还要用根内检查、no-follow 与原子 no-replace 做第二层路径
  防护。终态对象在 driver DELETE 成功后先 CAS 记录 `bytesDeletedAt`，安全保留窗口后再删除 metadata，
  避免重复外部删除和无界 tombstone 增长。
- 配置仓库只保留账户中立模板;Cloudflare account、域名、资源 ID 与登录态在本地 provision 或平台侧管理。

## 评审规则

- 安全字段同时做客户端快速反馈与服务端权威校验;历史脏值无法证明安全时 fail closed。
- 删兼容代码时只删项目内部旧预览形状,不删 MCP 世代互操作、Help DSL 未知项忽略、S3-compatible 能力或真实上游差异。
