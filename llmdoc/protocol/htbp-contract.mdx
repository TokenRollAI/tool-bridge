# HTBP 协议契约

精确 schema 以 core 类型、builtin help 和当前代码为准。

## 契约单一真源

固定控制面的请求/响应 Zod schema 位于 `packages/core/src/protocol/wire.ts`：app 路由门禁、`@tool-bridge/sdk/client` 运行时校验与 OpenAPI 3.1 artifact 从同一份 schema 投影。OpenAPI 只静态描述 health/help/tree/search/OAuth/feedback/registry 等固定面；运行时动态 HTBP 命令仍以 `~help` 发现为准。生成类型或 OpenAPI 文件都不能代替网络边界的 runtime validation。

builtin、Context 与 Skillhub 的命令使用 `HtbpCommandRegistry` 注册一次，同时投影 Help metadata、scope、strict Zod 入参与 dispatch handler。不得再分别维护 command 名清单、Help switch、scope switch 和 invoke switch；宿主或 capability 差异通过裁剪同一注册表表达，而不是再造一套 schema。

## 表示与错误

- `GET /<path>/~help`:默认 Markdown;`Accept: text/plain` 返回 Help DSL;`Accept: application/json` 返回 Help JSON。
- `GET /<path>/~tree?depth=N`:经身份可见性裁剪的树。`POST /~search`:仅当宿主声明 search capability 时存在。
- `GET|POST|DELETE /<path>/~feedback[/<id>]`:具体路径的使用反馈、投票与管理;不是集中 builtin。
- `PUT /~store/uploads/<uploadId>` 与 `GET /~store/refs|shares/<token>` 是 Store 的 bearer 数据面,不是 Registry 节点;精确授权见[Store](#store)。
- `ALL /~mcp`:把当前身份可见工具投影为 MCP server。`GET /healthz`:公开健康信息,不证明认证数据面可用。
- 错误统一 `{code,message,retryable}`;主要 code:not_found、permission_denied、invalid_argument、conflict、unavailable、rate_limited、internal。
- 未知 Help DSL 行与未知可选 capability 应忽略(协议演进能力);安全字段和未知写入参数不得静默忽略。

## 调用

- 唯一形态:`POST /<nodePath>/<command>`,body 即 arguments 本体。命令是节点下的**虚拟叶子**(不写 Registry),对一切可调用 kind 一视同仁;没有 `{tool, arguments}` 信封。
- 节点本身(无命令段)不可调用,返回 404。命令可寻址:`GET /<nodePath>/<command>/~help`;`~tree` 只列权威注册拓扑,动态命令经 `~help`/`~search` 发现。
- **`cmds[].path` 是可执行的完整路径,不是 owner 定位或展示提示**。owner 的 `~help` 返回的每条 `cmds[].path` 都已含命令叶子(如 `/device/mac/shell/exec`),消费者必须原样用于 `GET <cmd.path>/~help` 与 `POST <cmd.path>`,除 URL 拼接所需的前导斜杠规范化外不得改写。禁止用 `node.path + cmd.name` 重建命令身份、另传 `tool` 字段,或把 body 包成信封。Dashboard 的 `CmdPanel`/`CliHint`、`tb call` 与 curl 示例共同信任这一个字段,任一处重建都会同时失真。
- 标识符大小写不敏感、规范化为小写:路径段、命令/工具名、export id、scope pattern 字面段、device 暴露路径。规范化后冲突(上游同时暴露 `Foo`/`foo`)→ `invalid_argument`,不选其一。命令名含 `/`、为空、以 `~` 开头、为 `.`/`..` 一律拒。第三方原始工具名是外部身份,适配器维护 `公开小写名 → 上游原名` 映射。
- `Page<T>` 为 `{items,cursor?}`,默认 limit 50、最大 200;cursor 只表示继续位置,不是授权凭据。

### 两层 wire 不可互相套用

| 边界 | URL | body | `tool` 的含义 |
|---|---|---|---|
| 调用方 → HTBP gateway | `POST <cmds[].path>` | 裸 arguments 对象 | 不存在;命令身份已在路径叶子中 |
| gateway → plugin/v2 | `POST <manifest.endpoint>`(固定 endpoint) | `{tool, arguments}` | plugin 内部方法名,由平台适配层生成 |

公开请求向 owner 路径发送 `{tool, arguments}` 必须拒绝(当前为 404)。反过来,全仓清理公开旧信封时**不得**删除 plugin/v2 适配层的合法内部信封——按 `{tool,arguments}` 字面量机械搜索替换会同时漏掉公开路径漂移并误删合法内部协议。

wire 变更不能只测"手写正确 URL 能调用"。每个受影响 kind 至少跑通一条发现驱动闭环:请求 owner 的 JSON `~help` 并精确断言目标 `cmds[].path` 等于含叶子的完整路径 → 不重建 URL,直接用返回的 `cmd.path` 加裸 arguments 发起 POST → 用同一个 `cmd.path` 请求命令级 `~help`,确认发现、帮助与执行指向同一命令身份 → 真实发送旧形态 `POST /<owner>` + `{tool,arguments}` 并断言被拒绝。路径和 body 用精确结构断言;模糊子串、从 fixture 手写正确叶子路径,或分别验证 help 与 invoke,都不能证明闭环。审计范围还要覆盖 smoke、验证脚本、示例与运维 helper——这些迁移后仍可编译却继续生成旧 URL,只有消耗外部资源时才会暴露漂移;优先把 URL/body 构造抽成可离线断言的纯函数。

## 节点

`NodeKind`:directory、mcp、http、builtin、context、device、remote、tool、skillhub。常见配置:mcp(URL、headers、authRef/OAuth、virtualize)、http(base URL、工具定义、认证引用)、tool/context(provider、export?、authRef?、providerConfig?)、remote(baseUrl、skRef;受 host allowlist、Via 环与跳数限制)、device(由设备 hello 代写)、skillhub(R2/S3 技能存储)。

所有路径先规范化;保留段与保留根在服务端权威拒绝。`virtualize` 的 hide/rename/prefix/describe 只改投影视图,不改上游身份。remote host allowlist 为空时拒绝所有联邦目标;生效集合是部署期 env 基线与 `system/federation` 运行时条目的并集,env 条目不可经 API 删除。remote 出站身份只从自身 `skRef` 解析,不转发本地调用者 SK。

## 权限

Action:read、write、call、register、admin。scope 用完整路径 glob,deny 优先;`scopes: []` 表示无权限;不可见路径以 404 表达。注册路径还受 SK 的 `registerPaths` 约束;调用者 SK 不向上游透传。

节点归属:`system/registry` 的 write/delete 若目标已被他人 SK 注册(且非 `system:auto` 物化),默认 `conflict`;持目标路径 `admin` scope 者例外,可接管或清理他人节点——`register` scope 仍须通过。

## Feedback

Feedback 附着在具体节点或其工具子路径,根路径不接受。`GET` 需目标路径 read;`POST`(提交/投票)还需 call;`DELETE` 需 admin;read 不通过按可见性规则 404。条目按净分与时间排序;默认可见头部条目以精简形状进入该路径 `~help`,宿主装配 Search 时同批头部反馈进入派生索引。三宿主权威状态均为强一致 SQL 后端,投票与提交即时可读;feedback 是低频、非权威协作数据。

## plugin/v2、Context 与 Store

Manifest 描述部署:`id`、`protocolVersion:'plugin/v2'`、`endpoint`、`auth`、`healthPath`、`enabled`;`~describe` 描述 exports(profile、methods/capabilities、auth、凭证字段、挂载配置、可选 probe)。内置流程从编译期 catalog 直接挂载;外部 HTTP(S) endpoint 需注册、探活、校验 descriptor;自定义宿主显式装配 `binding:<name>`。

`endpoint` 是平台到 plugin 的**固定内部传输入口,不是公开 HTBP 命令路径**;调用体保留 `{tool:<plugin 方法>, arguments:<命名参数>}`。公开调用先在 gateway 以完整命令路径和裸 body 完成路由,再由 provider 适配层转换为该内部信封(边界表见[调用](#调用))。

Context 动词全小写且 cmd 名 = provider 方法名:`list`、`get`、`write`、`update`、`delete`、`search`,全部可选,能力由 handler 存在性推导。content 可内联或返回 `$ref`;大对象 URL 须短期有效并受签名/宿主边界保护。skillhub 动词:`list`、`get`(带 `file` 参数取单文件)、`search`、`publish`、`remove`。

内置 R2/S3 context 在底层 `ObjectStore.presignPut` 可用且挂载非只读时，额外声明 `direct-upload` capability 与 `POST /<context>/create_upload`（write scope）。请求体为 `{path,contentType,overwrite?}`；响应为 `{uri,method:'PUT',url,headers,expiresAt}`。`path` 经 context entry 规范化后固定到 namespace 的 keyPrefix，返回 headers 必须由上传方原样发送。

`overwrite` 缺省 `false`，此时 `If-None-Match: *` 与 `Content-Type` 一同进入签名；目标已存在时对象存储返回 412，CLI、Dashboard 与 Device SDK 统一映射为 `conflict`。只有显式 `overwrite:true` 才签发可替换对象的 PUT。grant URL 是短期 bearer secret：缺省 grant 可重复发送但只有首次创建成功，可覆盖 grant 在失效前可能重复覆盖；调用方只应持久化稳定 `node://...` URI。上传 body 直接到对象存储，不新增设备帧，也不经过 Context `write` 的 JSON 通道。

对象型 Context 与 Store 可复用 driver，但不能复用授权域。`__tool_bridge_internal__/store/v1` 是保留
物理 namespace：重叠的
非空 Context `keyPrefix` 在挂载时拒绝；空 prefix 仍可作为桶根挂载，但 list/search 过滤 Store key，read
按 `not_found` 隐藏，write/update/delete/create_upload 拒绝跨域修改。旧 `store/v1` 只属于未发布预览，
不再保留，Context 可继续使用该 prefix。

### Store

Store 是部署级私有对象能力，不是 `kind:'context'`。当前稳定身份严格为
`store://default/<22..64 位 base64url objectId>`；URI 本身不授权读取。Store 对象只支持服务端分配的新
identity，不接受 context path、entry path、bucket key 或 overwrite。owner/producer 使用通用非空
`OwnerRef`，Store 不另加 255 字符长度上限。

命令与 scope 的权威映射：

| 命令 | Action | 对象级约束 |
|---|---|---|
| `create_upload`、`complete_upload`、`abort_upload` | write | 普通路径以当前 owner 创建/修改自己的 session |
| `stat`、`read`、`list` | read | 只返回当前 owner 的 ready 对象；跨 owner 伪装为 not_found |
| `share`、`revoke_share`、`delete` | write | 只允许对象 owner；share 是短期匿名 bearer |

`create_upload` body 为 `{contentType,filename?,size?,checksum?,idempotencyKey?}`，返回统一 grant：
`{uploadId,objectUri,transport,method:'PUT',url,headers,expiresAt,maxBytes,uploadToken,...}`。grant 中 URL、
headers 与 token 都是 secret，不得进入日志或结果。relay 用 `x-tb-store-upload` header 调
`PUT /~store/uploads/<uploadId>`，成功 PUT 当次原子推进 ready 并返回 descriptor；presigned PUT 完成后
必须调用 `complete_upload` 做 HEAD 校验，complete 幂等。presigned transport 只在声明精确 `size` 且
backend 的 `presignPutExact` 将 `Content-Length` 纳入签名时签发；未知 size 或只有普通 `presignPut` 时
必须 relay。普通 idempotency 在 owner 域验证 producer；call 域还绑定 producer + call id，不能跨普通
上传或另一 call 恢复 session，身份/声明矛盾均为 `conflict`。

远程设备 call 的 create 路径用 `x-tb-store-capability` header；capability-only complete/abort 与 relay
PUT 用 `x-tb-store-upload`。对应 bearer 只允许在专用 header，`callCapability`、`capability`、
`uploadToken`、`shareToken` 等请求 body 字段必须拒绝。专用 header 缺省时同一路径继续走普通 SK
鉴权，不能因 capability route 绕过 HTBP scope。

`read` 返回短期 `$ref` 到 `GET /~store/refs/<token>`；`share` 返回可撤销 share id 与
`GET /~store/shares/<token>`。两类 bearer route 位于普通 SK 中间件之前，却都重新检查 token、到期和
对象 ready 状态；失败统一 404，capability path 在日志中脱敏。`list` body 为 `{opts?:{cursor?,limit?}}`，
仅分页返回当前 owner 的 ready descriptor；公开 descriptor 保留 status、owner、可选 producer/
originCallId 与生命周期字段，不含 driver key 或 capability。完整状态机与宿主限制见
[default-store](../store/default-store.mdx)。

## 设备

设备连 `/system/device/ws?deviceId=...`,hello 声明 expose;服务端验证身份与 `registerPaths` 后代写 `device/<id>/...`。帧集合:hello、ready、error、call、result、ping、pong、cancel。`call` 帧 `path` 相对 mountPath 且**含命令叶子段**,与直连调用一致。PING/PONG 是稳定字面量支持边缘 auto-response;只有当前 generation 进入 ready 后才能执行 call,连接替换后旧 generation 的消息与迟到结果不得污染新连接。

call id 在同一设备进程内用于执行合并与有界结果缓存,不承诺跨进程 exactly-once。cancel 是协作式提示(AbortSignal),不能表述为外部副作用已撤销。call 帧可选 `context`(caller.keyId/owner、traceId、createdAt、expiresAt)由网关鉴权后签发,不接受来自 arguments,故意不含 scopes/SK;授权判定全在网关侧,设备只做审计与限时,`expiresAt` 以网关时间为准。Store 可用时 wire 还带 `context.upload:{token,expiresAt,maxBytes,maxObjects}`:它只允许本次 call 创建受数量/字节/MIME 约束的新对象；SDK 内部消费 token，handler 的 context 只暴露非 secret 限额并通过 `call.uploadObject` 上传，服务端 reservation/CAS 权威记账，返回后网关撤销。token 不得进入 arguments、result 或日志。老网关不带 context/upload 时新设备按缺省降级;老设备 decoder 忽略未知字段。

设备在线状态是三态 `presence: { state: 'online'|'stale'|'offline', lastSeenAt? }`:存储层 `online` 位结合 `lastSeenAt` 在投影时派生,online 但心跳超时降级 stale。presence 只是发现提示,可路由性以宿主活动 socket 为准;wire 派生只发生在树/help 投影处,读路径不回写权威状态。`@tool-bridge/sdk/device` 安全作者面只声明可路由回设备的 tool/context 节点;移动端默认前台实时在线,后台任务属于另一个异步队列/推送能力。

## CLI 契约

顶层命令族以 `packages/cli/src/program.ts` 为准。全局 `--json`、`--base-url`、`--sk`、`--timeout` 可位于根/组/叶子;未知 flag、多余 positional、缺必填参数均失败。Store 管理面为 `tb store upload|stat|get|share|revoke-share|rm|list`(`list` 可写 `ls`),与 `system/store` 对等;除用户明确执行 `share` 时的成功输出外,人类/JSON 输出与错误都裁剪 `$ref`、签名 URL、headers 与 token。集成入口只接受 `--credential`,卸载无隐藏 `--purge`,凭证清理由 `tb secret` 显式完成。CLI 与 Dashboard 的便利校验不替代服务端权威校验;`tb daemon` 是本地生命周期入口,不适用三入口对等。
