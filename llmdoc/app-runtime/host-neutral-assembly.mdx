# 宿主中立装配

`app` 持有 Hono 路由、发现/调用、provider 编排与依赖注入面；`server` 负责 Node 监听、PG、S3 和受管理启动。共享安全链留在 core/app，服务端实现通过接口注入；neutral SDK 子入口不能沿装配依赖触达 Node 驱动。

## 注入与 fail closed

`TbAppDeps` 的基础依赖是 `state`、`secrets`、可选 `objects`、`device` 和 `search`。需要 Store 的宿主另注入 `storeRepository` 与 `storeBackends`；Mailbox 另需 `mailboxRepository` 与加密根/keyring。optional 表达可选能力，不是旧宿主兼容承诺；缺少领域依赖时相关功能 `unavailable`，不能退回 KV 或内存锁模拟事务。

S3 类型 `S3StoreConfig` 可留在 app；实际 SDK/transport 由宿主 `s3Objects` 工厂提供。平台 `provider:'storage'` Context 使用 `defaultObjectBackend` 在注册时绑定 backendId，后续从 `objectStoreForBackend` 解析原身份，找不到不能偷偷用 active。直接 S3 Context 仍是显式独立连接；标准 Node AWS driver 没有 presigner，因此不广告 `direct-upload`，Context 二进制直传能力不能凭“配置了 S3”推断。

Store 的 relay/direct grant、ref/call capability 与 cleanup 装配集中在 `store.ts`，`routes/store.ts` 只处理 capability-only 控制/数据面。Store 后端状态与身份归 [Default Store](../store/default-store.mdx)；S3 adapter 安全与能力验证归 [存储后端](../store/storage-backends.mdx)。相同字节服务可承载 Context 与 Store，但 Context provider 强制保留 namespace firewall。

`DeviceChannel` 只负责 realtime attempt，并返回 `completed|not_dispatched|unknown`。Mailbox 由 `deviceMailbox.ts` 构造领域服务、`routes/invoke.ts` 解释普通 command POST 中的 `~delivery`；只有明确未分发才能 fallback。它不借活 WebSocket 承载 operation，也不延长 realtime Store capability。

## 管理面装配

core 的 builtin 模块声明和 schema 是 Help/调用的共同真源。`routes/env.ts` 按宿主注入追加 config、storage、deployment、maintenance、keys 与 Store 模块；未注入的管理能力不能伪装为已可用。宿主维护钩子处理实际重启、停写和持久状态切换，不把这些逻辑塞入 Hono 路由。

管理模块要求对应规范 system 路径的 admin 权限，普通 SK 即使有 system 路径 write 也不能修改实例配置或存储凭证；调用前后只记录 actor/action/outcome 等脱敏审计。`~setup` 是 managed 外层监听器的独立配对面，不经过 PG 业务鉴权，也不接受普通 Admin SK 代替本机配对。

## 共享 owner

- `registryMutation.ts` 统一 `system/registry` 与 `~register` 的注册路径、secret reference、OAuth/config 与出站探测顺序；派生工具缓存、MCP era 与 OAuth 记录整体失效。device hello 的异构写入归 `deviceHello.ts`，共享同一注册/保留根权威。
- `deviceLifecycle.ts` 统一凭证/注册权限重验、断线下线和子树回收顺序；Node DeviceHub 只持 timer、连接代际与宿主 meta。
- `cursorCleanup.ts` 统一持久进度、有界分页与 CAS 推进。Store/Mailbox 各自持状态转换，Node 只调度清理 tick，清理不在普通请求扫描全树。
- `uiAssets.ts` 处理静态资源协议，宿主提供资源源；hash 资产 immutable，入口 no-cache，压缩协商和条件请求须保持真实浏览器可用。

每个 HTTP 请求先同步 PG 已应用配置 revision，再拿一个不可变 app snapshot；更新中的旧请求保留原快照，已发 grant 的限额/期限不追溯扩大。TLS 代理下 `canonicalOrigin` 只为 Store 数据面校正可信 protocol，host/port 仍沿当次请求 alias；不信任 `X-Forwarded-Proto`。OAuth redirect 的 canonical 绑定是独立用途，不能混同。

## app 内部代码地图

### Search 与 remote path 投影

`POST /~search` 的本地路径由 `search/localSearch.ts` 执行，默认 compact/best/10。它可批量 over-fetch
轻量候选，但在出 wire 前必须重新读取 canonical node/tool，重做 read+call、virtualize 与 effect 复核；
索引不是授权真源。SearchSynchronizer 仍只物化 mcp/http/tool，不索引 remote。

`search/federatedSearch.ts` 是 query-time coordinator：只选择当前 registry 的 direct remote mounts，分片
source/time budget，要求 child `search:federated` capability，用 portable coverage 做 source-balanced merge，
严格投影/复核 child hit。`search/federatedSession.ts` 用 StateStore CAS 保存固定尺寸 handle 对应的 immutable
generation 与原子 quota；内部 child snapshot validation 递归绑定 A→B→C 后代 revision。只有显式
instanceId + CAS + SearchIndex revision 齐全时才广告 federated capability。

generic remote fetch 固定 `redirect:'error'`，任何 30x 都 fail closed；按调用方提供的 signal/cap 流式
读取 body，超时或超限取消 reader。remote `~help/~tree` 的成功体不再原样透传：
`RemotePathProjector` 严格校验 child canonical path、direct descendants 与 command containment，rebase 到
本地 mount；tree 后代还逐条重做外层 read/call scope。A→B→C 已覆盖 search/help/tree 路径闭环；普通
call wire 不变。
