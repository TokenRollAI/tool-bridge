# Device Mailbox 离线投递跨层断裂反思

## Task

- 修复设备离线时无法从 Dashboard 发起 Mailbox/fallback，以及设备重连后 CLI 没有消费已入队 operation 的问题。

## Expected vs Actual

- 预期：presence 只描述 realtime 可路由性；离线设备的 mailbox-capable command 仍可发现并入队，设备重连后由本地 installation 主动 claim、执行、complete。
- 实际：服务端一直允许这条路径，但 Dashboard 在请求发出前删掉了整个 offline 设备子树；即使绕过 Dashboard 成功入队，CLI 运行时也只启动 WebSocket realtime supervisor，没有接入 SDK 已提供的 pull processor。

## Evidence

- `packages/app/src/routes/invoke.ts`（device invoke 分支）与 `packages/app/src/routes/deviceMailbox.ts`（`enqueueDeviceCommand`）：Mailbox 入队不以 presence 为前置条件；fallback 只依赖 realtime dispatch certainty。
- `packages/app/test/deviceMailbox.integration.test.ts`（`keeps an offline device command discoverable and enqueues fallback`）：把 registry 设备显式设为 offline 后，`~help` 仍可发现命令，fallback 返回 mailbox `202 queued`。
- 修复前的 `packages/dashboard/src/canvas/useCanvasTree.ts` 与 `packages/dashboard/src/lib/presence.ts`：`pruneOfflineNodes` 在根树和懒加载子树进入画布前递归删除 offline 设备，因此用户无法到达命令调用面。
- 修复前的 `packages/cli/src/deviceRuntime.ts`：只创建 `openPortableDeviceConnection`；`packages/sdk/src/device/mailbox.ts` 已有 `createDeviceMailboxProcessor`，但 CLI 宿主没有创建 processor、durable journal 或在 reconnect ready 后 drain。
- 当前回归分别固定了 offline 图节点保留、CLI ready→drain 生命周期和 installation-local journal 的 executing barrier；相关 app、Dashboard、CLI 定向测试均通过。

## Root Cause

- 把 presence 错当成了“能力可见性”。offline 只能否定 realtime socket，并不否定设备身份、已声明命令或 durable Mailbox 能力。Dashboard 的性能/降噪剪枝越过了展示边界，实际改写了产品可达性。
- 把 SDK 能力存在错当成了宿主能力已交付。pull-only 的设计刻意不自启后台工作；若 CLI adapter 不显式提供 durable journal、复用 handler 并选择 drain 时机，服务端 ledger 只有生产者，没有消费者。
- 原有跨层测试覆盖 app + SDK 协议闭环，却没有穿过真实 Dashboard tree projection 和 CLI device lifecycle 两个最外层 adapter；各层局部正确仍能组成端到端断链。

## Missing Docs or Signals

- `llmdoc/dashboard/canvas-architecture.mdx` 仍把“offline 设备进入布局前剪掉”列为性能边界，与 `llmdoc/device/durable-mailbox.mdx` 的离线可发现/可入队契约冲突。这里应由 Mailbox 产品语义覆盖旧的 UI 剪枝规则。
- “Device SDK processor 不自启”虽然已有记录，但缺少宿主接入验收清单：processor、durable journal、共享 expose/handler、启动/重连 drain、停止时 abort 缺一不可。

## Promotion Candidates

- 在 Dashboard 架构中把规则提升为：presence 只影响状态呈现和 realtime 提示，不得删除 offline 设备或 mailbox-capable command；规模控制继续依赖懒加载、折叠和节点阈值。
- 在 Mailbox/CLI 指南中加入 host-adapter checklist，并明确“公开 SDK 已实现”不等于 CLI/daemon 已消费。
- 把跨层验收矩阵固定为三条纵向 seam：offline discovery→enqueue、Dashboard offline node→command invoke、CLI reconnect ready→claim/handler/complete/get。测试应断言用户可达结果，而不只断言单层 helper。
