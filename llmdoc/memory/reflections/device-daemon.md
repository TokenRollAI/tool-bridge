# Device daemon 产品化反思

- daemon 产品化不能只停留在“生成 service 文件”：安装、状态、日志、重启、卸载，以及断线重连与开机自启应形成完整生命周期。
- `install` 必须幂等。重复安装即使 unit 内容未变，也必须执行 restart，让新配置与凭据立即生效，不能把“文件相同”误判为“运行状态正确”。
- 安装过程需要事务式失败回滚：写配置、安装 unit、enable/start 任一步失败，都应恢复旧文件和旧运行状态，避免留下半安装或不可启动的 daemon。
- Device SK 必须与 unit 和进程 argv 隔离，放入权限为 `0600` 的 daemon JSON 私有配置文件；unit、命令行与日志均不应泄露 SK。
- 验证工具链本身也可能制造假象：仓库的 pnpm 版本包装器曾让命令看似执行、实际没有运行目标校验。最终验收必须使用项目锁定的真实 pnpm 版本执行 `verify`，并检查退出码与实际测试输出，不能只凭包装器输出判断通过。
