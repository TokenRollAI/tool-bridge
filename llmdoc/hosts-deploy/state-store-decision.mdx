# PostgreSQL 权威状态与领域仓库

标准 Node 服务只支持 PostgreSQL。删除旧宿主与数据库适配是运行契约变化：未初始化实例进入安装面，已初始化实例不能把数据库缺失或故障解释成全新空实例。数据库的 `tb_instance` 身份必须与受保护 bootstrap 一致，切库只通过显式维护流程。

## 存储责任

| 边界 | 权威内容 | 约束 |
|---|---|---|
| `PgStateStore` | 节点、SK、加密 secret、通用配置/派生进度 | JSON KV 提供原子的 putIfAbsent/CAS；不缓存 SK 吊销 |
| `PgStoreRepository` | 对象、上传、幂等、call reservation、share、后端引用 | 多记录转换属于命名领域操作，事务不接受网络回调 |
| `PgMailboxRepository` | durable operation 与 lease | pending 配额与 enqueue 同事务，领取/完成按身份、revision 和租约条件更新 |
| `PgSearchIndex` | 可重建搜索候选与 cursor revision | 不是授权真源，响应前仍 hydrate canonical state |
| S3 | 对象字节与条件写 | backendId 固定，字节成功不等于业务对象已 ready |
| Redis | 跨副本设备路由与瞬时通知 | 不保存唯一权限、operation 结果或对象元数据 |

领域仓库采用受类型约束的 JSONB 记录，加 generated columns、外键、唯一约束与查询索引。它没有引入通用 ORM/事务 DSL，也未把所有业务字段机械拆成列。选择标准 SQL 事务是为了保护实际跨记录不变量，并保留 core 的业务语义；新增原子操作应继续明确命名，不向 core 暴露数据库句柄或 transaction callback。

Store `beginUpload` 在同一事务内绑定幂等身份、读取并锁定 active 后端、锁定 call capability 预留额度，再创建对象/会话；失败全部回滚。`finishUpload` 与 `terminateUpload` 同时推进对象/会话，旧 revision 或竞争终态不会覆盖 ready。owner 列表用 owner/status/id 索引，不再先扫全量对象后过滤。

Mailbox enqueue 用每设备 advisory transaction lock 保护准确 pending 计数及幂等插入。claim 候选先由 core 复核权限，PG 条件更新再次确认 immutable device/key 身份、revision、总 TTL 与可领取状态；renew/complete 再比较 leaseId 和未过期 lease。它不是 FIFO，也不承诺跨设备安装的 exactly-once。

Schema 创建/升级使用受 advisory lock 保护的 PG 事务；失败阻止业务就绪。新部署没有旧 KV/SQLite 导入、双写或兼容 keyspace。SDK 嵌入者必须显式注入所需领域仓库；测试内存实现不是生产持久层。
